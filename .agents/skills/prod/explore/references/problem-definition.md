# 问题定义（8 要素，可选）

## 用途

把调研中发现的痛点，从「现象描述」升级为**可取证、可量化、可归因**的业务问题。为 idea 的业务意图、Exit Criteria 与 Story 业务规则提供依据。

产物模板：`openspec-requirements/templates/problem-definition.md`

## 8 要素

| # | 要素 | 判定口径 |
| --- | --- | --- |
| ① | 一句话问题描述 | 主谓明确，含「导致…」后果 |
| ② | 业务角色和场景 | 角色清单 + 一个典型触发场景 |
| ③ | 遇到的问题 | 可观察现象，能对应调研记录 |
| ④ | 问题根因 | 归因到系统/规则/数据/治理，非个人 |
| ⑤ | 发生频度 | 频次 × 请求量 × 场景占比 |
| ⑥ | 影响范围 | 角色链路 + 渠道 + 系统边界 |
| ⑦ | 每次发生的影响 | 有单位：时长/成本/错误率 |
| ⑧ | 累计影响 | N 次叠加后的 KPI/战略后果 |

## 硬规则

1. 每条结论必须能回溯到 `research.md` 的访谈记录或业务数据。
2. 根因未确证时标注「待验证」，不得写成事实。
3. 量化口径必须写清基数、时间范围与来源。
4. 不写解决方案；方案属于 idea / To-Be。

## 使用时机

- `explore` 阶段**可选**，不阻塞漏斗。
- 做与不做由 Epic 复杂度决定；建议至少覆盖 1 个核心问题。
- 产物落位 `epics/<epic-key>/analysis/problem/problem-definition.md`，并在 `idea.md` 引用。
