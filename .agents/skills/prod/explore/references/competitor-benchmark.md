# 竞品与参考案例（可选）

## 用途

在方案成形前，用外部同类实践校验设计取舍。只回答三件事：
1. 外部有人做过吗？形态与交互是什么？
2. 他们付出了什么代价、什么前提才成立？
3. 我们该照搬 / 改造 / 差异化 / 放弃？

## 五步

| 步 | 做什么 | 门禁 |
| --- | --- | --- |
| 1 立参考点 | 从 idea 的 To-Be 与业务问题推导 6–10 个可判定设计问题 | 锚不上 idea 的参考点删掉 |
| 2 双圈选样 | 同业 + 异业，按任务结构同构选样 | 8–12 张卡；异业 ≥2、反例 ≥1 |
| 3 取证分级 | A/B/C 三级；效果须有指标名/基数口径/时间范围 | 无来源不进正文；无量化写「未披露」 |
| 4 案例卡 | 圈层与同构度 / 任务链 / 产品设计 / 落地实践 / 效果 / 可借鉴 / 迁移前提 / 不能外推 | 必须写清 AI 与人的分工边界 |
| 5 映射取舍 | 共识区 / 分歧区 / 空白区 → 每条取舍带 stance 与回写 | 空白区标注「须自建验证」 |

## 硬规则

1. 不做竞品打分排名、市场格局报告、供应商选型。
2. 不把「未披露」写成估算事实。
3. 取舍必须回写到 idea 的具体章节，而不是停在报告里。

## 使用时机

- `explore` 阶段**可选**，建议在 prototype 之前。
- 产物落位 `epics/<epic-key>/analysis/competitor/competitor.md`。
