# 访谈提纲设计（调研前置）

## 用途

在正式访谈前，基于 Epic 背景生成一份**可直接照着问、也能直接在题下记录**的提纲。提纲是访谈工具，不是访谈结果。

产物模板：`openspec-requirements/templates/interview-outline.md`

## 三段骨架

| 段 | 内容 | 覆盖 |
| --- | --- | --- |
| 一、角色与业务背景 | 角色与团队 / 目标与考核口径 / 核心业务全周期 | 语境 |
| 二、信息流现状 | 信息捕捉与研究 / 信息分析与判断 / 信息处理、决策与记录 | 捕捉 → 处理 → 决策 → 复用 |
| 三、理想态与资源重排 | 理想方式 / 资源重排 / 管理者视角 | 理想态 |

- 「核心业务全周期」按场景实例化：销售线=客户生命周期、服务线=工单全流程、项目线=项目周期、职能线=事项处理全流程。
- 时长紧张时可压成两段：把「三、理想态」并入「二、信息流现状」末尾。
- 场景差异靠**术语替换 + 探针内嵌**，不新增段落。

## 硬规则

1. 只出提纲本体，不加附录、不写填写模板。
2. 每小节 ≤ 4 题；★ 必问 ≤ 40%；单册 ≤ 约 45 题。
3. 只还原现状，不评价、不引导方案；避免「如果有个工具你会不会……」。
4. 提纲即记录纸：现场在题下直接记，事实 / 感受 / 期望分开标注。

## 完成判据

- 三段齐全，题目可被直接提问；
- 每个核心业务环节都有对应问题；
- 提纲已随 `research.md` 的「调研对象与方式」一并确认。
