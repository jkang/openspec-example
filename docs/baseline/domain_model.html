Purpose

规范化建模看板

本页不是“实体列表”，而是对系统核心业务语义的结构化表达：谁负责什么、对象之间如何引用、 状态如何迁移、事件在何种规则下触发，以及各个 Bounded Context 之间如何通过事实协作。

1. Bounded Context Map

用上下文边界而不是技术模块来定义系统职责。重点描述 Catalog、Cart、Coupon、Order、User 之间交换的业务事实，以及哪些规则在边界内被维护。

2. Core Business Object State Machines

选择一个核心业务对象，查看它的状态迁移、触发事件以及规则约束。这里强调的是业务状态机， 不是技术流程图。

3. Core Domain Object Relationship Graph

表达 Aggregate / Entity 之间的包含、引用与结算生成关系，并把关键业务不变量直接挂到关系上， 避免只看到“线”，看不到“规则”。

4. Event Storming Structure

按 Event Storming 的标准层次整理 Commands、Domain Events、Policies 与 Read Models， 让“行为”与“结构”同时可读。

5. Aggregate Catalog

对当前系统的核心 Aggregate 做标准化说明：根实体、主要实体、值对象与关键业务约束。

6. Bounded Context -> Capability Mapping

明确 Bounded Context (业务边界) 对 Capability (Spec 契约) 的治理关系。 这是从 Baseline 层推导 Spec Flow 影响范围的核心桥梁。
