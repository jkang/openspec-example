Service Blueprint

将高层用户旅程升级为服务蓝图视图：最上层呈现买家视角的端到端流程与系统 Feature， 中间层呈现电商运营的核心活动与支撑能力，最下层呈现后台实现与支撑能力。 所有能力命名优先对齐 `domain_model.html` 中的 Capability taxonomy。

Baseline / Last Updated: 2026-08-30

Purpose

把“旅程”提升为“服务协同结构”

这份蓝图不再只描述买家看见的步骤，而是把前台体验、运营动作和后台能力放到同一张图里。 这样可以直接回答三个问题：用户此刻在做什么、运营靠什么支撑这一步、系统由哪些 capability 负责兑现。 图中实线框表示当前代码库中已有主规格或实现证据的能力；虚线框表示治理上已识别、但尚未形成当前主规格闭环的能力。

Scope Summary

客户主线
商品发现 → 加购 → 结算确认 → 提交订单 → 模拟支付 → 成功回流（注册/登录/会话贯穿，订单归属真实用户）。
运营主线
商品发布与库存维护、优惠券配置与门槛控制、订单与支付结果追踪、用户管理（列表/检索/详情/禁用启用，仅运营角色）。
能力边界
Catalog / Cart / Coupon / Order / User 五个 Bounded Context 负责治理对应 capability；Shared / Cross 承担 UI、治理模型与异常规范。
阶段
Stage 01

触达与发现

首页进入、商品浏览、搜索与排序、单品详情查看；顶部登录/注册入口（账户体系）。

Stage 02

选购与加购

挑选商品、录入数量、加入购物车并同步状态（登录用户购物车跟随账户）。

Stage 03

结算确认

进入结算页、自动推荐最优券、确认优惠后金额；未登录引导注册/登录（身份前置）。

Stage 04

提交订单

把购物车转成订单，完成库存与金额校验；订单归属当前登录会话用户。

Stage 05

模拟支付

通过支付接口完成 PENDING_PAYMENT → PAID 的状态流转。

Stage 06

成功回流

展示成功页与订单详情，并把用户带回下一轮浏览；「我的订单」按登录用户归属查询，B 端可按用户聚合回查。

客户视角 E2E 流程

这里强调买家真正感知到的步骤，以及界面层暴露出来的 feature。

客户动作

  • 进入商城首页
  • 搜索商品名称 / 按价格排序
  • 打开商品详情确认图片与库存
  • 注册账户（手机号+昵称+密码）或登录（恢复身份，R-REG/R-LOG）

系统 Feature

catalog-management 商品列表、排序、库存可见性；分类筛选条（仅展示上架商品）
product-query 按 ID 查询单品详情
account-management 注册/登录：手机号唯一、密码哈希、禁用拦截
user-session 登录/注册成功创建持久会话凭证
frontend-ui 商品栅格与搜索交互、登录/注册视图

客户动作

  • 选择规格与数量
  • 加入购物车
  • 看到购物车状态实时更新（登录态购物车跟随账户）

系统 Feature

cart-management 加购、数量累加、移除与清空（有会话按会话 userId 归属）
frontend-ui 本地状态必须与后端返回严格同步

客户动作

  • 进入结算页
  • 未登录被引导注册/登录（回跳原页面）
  • 查看推荐优惠券与折扣结果
  • 确认应付金额与优惠说明

系统 Feature

checkout-management 购物车转结算态
coupon-management 最优券推荐与门槛校验
order-management 持久化 total / discount / actualPaid
account-management 结算前身份确认（未登录引导注册/登录）

客户动作

  • 点击提交订单（携带会话凭证）
  • 等待校验与创建结果
  • 感知到订单编号生成

系统 Feature

order-management 订单创建与幂等保证；归属当前会话用户（R-SES-007）
checkout-management 结算触发与成功反馈
user-session 会话全局校验：未登录/禁用即拦截（401/403）

客户动作

  • 完成模拟支付（结算成功弹窗「模拟支付」按钮）
  • 确认订单由待支付变为已支付（库存已扣减反馈）

系统 Feature

payment 模拟支付交互；支付成功与状态流转
order-management 承接支付后的订单状态确认

客户动作

  • 查看 Checkout Success 页面
  • 查看「我的订单」列表与实时状态（待支付/已支付/已发货/已完成/已取消）
  • 确认订单详情（商品快照/金额/状态轨迹）
  • 继续购物，重新回到商品浏览

系统 Feature

frontend-ui 成功模态框 / 成功页规范
order-management 订单详情读取与展示；我的订单按会话 userId 归属查询（R-SES-003）
user-session 未登录访问我的订单被引导登录（回跳）；禁用即引导重新登录

电商运营层

这里展示运营如何支撑前台体验，包括商品、营销和订单观察面的核心活动。

核心活动

  • 录入商品名称、价格、图片、库存
  • 维护可售商品池与展示顺序
  • 修改商品价格、库存、详情；下架失效商品
  • 维护分类（新增/编辑/下架）；给商品挂分类

支撑 Capability

catalog-management 商品上架、修改（改）、删除/下架（软删除）；分类管理

核心活动

  • 关注高库存商品的转化表现
  • 确保商品仍然可售、价格有效
  • 价格/库存修改后即时反映到 C 端

支撑 Capability

catalog-management 价格与库存事实维护（修改即时生效）
error-handling 异常加购反馈仍缺少主规格沉淀

核心活动

  • 创建 FLAT / PERCENTAGE 优惠券
  • 设置 minSpendCents 与有效期
  • 手动单人发券（模板生成用户归属实例）
  • 驱动“自动推荐最优券”体验

支撑 Capability

coupon-management 优惠券定义、校验、核销；规则配置与发放归属
checkout-management 在结算节点暴露推荐结果

核心活动

  • 确认订单创建后优惠券已锁定
  • 关注库存扣减与购物车清空是否一致

支撑 Capability

order-management 订单生成、金额持久化
catalog-management 库存扣减原子性；软删除下架不影响历史订单

核心活动

  • 确认支付成功并观察状态变化
  • 将订单推进到已支付状态

支撑 Capability

payment 支付接口与状态流转
order-management 订单支付结果承接

核心活动

  • 查看成功交易结果
  • 查看订单列表/详情（订单号/金额/商品快照）
  • 发货（PAID→SHIPPED）与取消（仅待支付→CANCELLED）
  • 以订单数据复盘营销效果
  • 用户管理（运营角色）：按手机号/昵称检索用户、查看详情与订单聚合、禁用/启用（R-ADM-001~007）

支撑 Capability

order-management 订单查询/发货/取消（B 端管理）
user-admin B 端用户管理：列表/检索/详情（订单聚合）/禁用启用；仅运营角色
frontend-ui 成功反馈、继续购物入口

后台核心活动

这里落到服务、接口和核心业务规则，用来说明前台体验背后的系统编排。

核心活动

  • `GET /api/products` 支持搜索与排序
  • `GET /api/products/{id}` 返回完整商品详情
  • 返回 `imageUrl / stock / priceCents` 等权威字段
  • 列表/搜索仅返回 active 商品；`PUT`/`DELETE /api/products/{id}` 维护目录
  • `/api/categories` 分类持久化；删除分类时商品 categoryId 置空

支撑 Capability

catalog-management 商品列表/搜索过滤 active；软删除持久化；分类接口
product-query 按 ID 读取详情

核心活动

  • `POST /api/cart/items` 写入后端权威购物车
  • 数量累加、数量上限校验
  • 购物车移除 / 清空能力供结算后回收

支撑 Capability

cart-management 用户购物车一致性与状态同步
error-handling 错误码体系未形成当前主规格目录

核心活动

  • 计算最优券并校验 minSpendCents
  • 处理百分比折扣的 cent 精度补偿
  • 把购物车项转换成订单项候选
  • 券规则持久化与单人发放接口（/api/admin/coupons*）

支撑 Capability

checkout-management 结算编排与成功反馈入口
coupon-management 推荐、折扣计算、核销规则
domain-model 金额字段与状态机语义基线

核心活动

  • 创建订单并写入 `PENDING_PAYMENT`（下单仅校验库存，不扣减）
  • 持久化 `discountCents / actualPaidCents` 并绑定优惠券
  • 成功后清空购物车并保证幂等
  • `/api/admin/orders` 列表（状态过滤/搜索）与 ship/cancel 接口
  • `GET /api/orders` 按会话解析 userId 返回我的订单（归属隔离，倒序，R-SES-003）
  • B 端用户管理：`GET /api/admin/users`（列表/检索）、`GET /api/admin/users/:id`（详情+订单聚合）、`PATCH /api/admin/users/:id/status`（禁用/启用）——仅运营角色（R-ADM-001）

支撑 Capability

order-management 订单创建、查询、总价计算；取消（仅待支付）；B 端列表/发货
catalog-management 库存扣减不可为负；商品 status 软删除
cart-management 结算成功后自动清空购物车
user-admin 用户列表/检索/详情（订单聚合）/启停 + 运营角色门禁
user-session 会话校验门禁（禁用即失效）供 B 端接口复用

核心活动

  • `POST /api/payments/:orderId` 推进支付（已落地）
  • 支付成功时扣减库存、核销优惠券，状态 → PAID
  • 状态机：`PENDING_PAYMENT → PAID → SHIPPED → COMPLETED` / `CANCELLED`
  • 重复支付时保持幂等语义；支付时二次校验库存

支撑 Capability

payment 支付接口与支付校验；扣库存/核销券
domain-model 订单状态机规则来源

核心活动

  • 读取订单详情并渲染成功反馈
  • 保留下一轮浏览的入口，不阻塞用户继续购物
  • 销售数据聚合（看板）：按时间维度聚合订单指标与商品/分类排行（只读，B 端运营/老板视角）

支撑 Capability

order-management 订单详情回读
frontend-ui 成功页与继续购物动作
sales-dashboard 销售看板：指标聚合 / 时间维度 / 趋势 / 商品分类排行（只读，data-insights BC）

跨阶段支撑能力

这些能力不是单一阶段的“一个动作”，而是横向约束整个交易旅程的共性支撑。

frontend-ui 已落地

统一前台呈现

承担商品卡片、搜索交互、成功反馈模态框等体验层规范， 让“发现 → 结算 → 成功”在视觉和交互上保持同一种语言。

domain-model 治理基线

领域语义对齐

负责把 Order、Coupon、Cart、Product 的状态机、对象关系与金额语义稳定下来， 是 capability taxonomy 和服务蓝图之间的治理桥梁。

error-handling 规划中

异常规范仍待主规格闭环

代码与历史提案里已经出现统一错误码诉求，但当前 `openspec/specs/` 下还没有主规格目录。 因此在蓝图中保留为虚线能力，提示其应补齐为真正的横切能力。

Capability 对照表

该表用于解释本蓝图如何映射到 `domain_model.html` 的 capability taxonomy，以及为什么某些能力采用虚线表达。

Capability 治理归属 状态 在蓝图中的职责
catalog-management Catalog Context 已落地 支撑商品列表、排序、上架、库存维护与下单时库存扣减。
product-query Catalog Context 已落地 支撑商品详情查询，服务于前台发现与选购决策。
cart-management Cart Context 已落地 支撑加购、移除、数量限制和结算后的购物车清空。
coupon-management Coupon Context 已落地 支撑优惠券配置、最优券推荐、门槛校验与核销。
order-management Order Context 已落地 支撑订单创建、查询、金额持久化和支付后的状态承接。
checkout-management Order Context 已落地 支撑从购物车到订单的编排，以及结算成功反馈入口。
payment Order Context 已落地 支撑模拟支付与订单状态流转。
frontend-ui Shared / Cross 已落地 支撑商品浏览、搜索、结算成功模态框等统一前台体验。
domain-model Shared / Cross 治理基线 支撑订单状态机、对象关系、金额字段定义，是蓝图的语义底座。
error-handling Shared / Cross 规划中 历史提案中已有统一错误码诉求，但当前主规格目录尚未形成，因此用虚线提示。
account-management User Context 已落地 承载 C 端注册/登录（手机号唯一、密码哈希、禁用拦截、自动登录）与 B 端启停产生的生命周期状态门禁。
user-session User Context 已落地 承载会话生命周期：创建/全局校验/持久化保持/退出销毁/禁用即失效，支撑订单归属与 B 端接口复用。
user-admin User Context 已落地 承载 B 端用户管理：列表/检索/详情（订单聚合）/禁用启用；仅运营角色（敏感信息保护）。

Source of truth: `docs/baseline/domain_model.html` capability mapping、 `openspec/specs/` 当前主规格目录，以及 `ecommerce/ecommerce-mini*` 中已存在的实现痕迹。 点击同名 capability 可在页面中高亮其所有出现位置。
