# 产品路线图 (Product Roadmap)

本文档定义了 OpenSpec-Practice 极简电商系统的高阶业务规划。

## 📅 当前状态与阶段规划 (Current State & Phasing)

最后刷新时间: 2026-08-23

### 🏆 当前 Baseline (已完成能力)

- **C 端交易链路**: 商品浏览 / 关键词搜索 / 价格排序 / 分类筛选 / 购物车 / 结算（模拟下单）。
- **B 端运营后台**: 商品管理完整 CRUD（含软删除）、商品分类管理（分类 CRUD + 商品挂分类）、优惠券规则配置与单人发放。
- **营销工具**: 优惠券系统闭环（B 端配置 → 发放 → C 端最优券结算核销）。
- **持久化与真实数据**: JSON 文件持久化（products/categories/coupons/orders/carts），真实商品与分类数据落地。
- **SDD 工作流**: 基于 OpenSpec 的规格驱动开发闭环（Epic/Story/Bug Fix/Tech Debt），12 个变更已归档。

### 🔍 现状评估 (Product Expert Review)

对照产品核心价值承诺（`docs/PRODUCT_SENSE.md`：*订单驱动库存实时变更* + *回款节点驱动应收账款看板*）：

| 价值承诺 | 现状 | 差距 |
| :--- | :--- | :--- |
| 订单驱动库存实时变更 | 下单扣库存（基础） | 订单无生命周期、无支付/履约/发货，B 端无法处理订单 |
| 回款节点驱动应收账款看板 | 未启动 | 无账户归属、无账期/回款概念，差异化承诺空白 |
| 运营可配置性（B 端） | 商品/分类/优惠券 | 订单管理、发货管理缺失 |

**结论**: 系统已具备"能下单、能配置"的基础，但**订单仍是无生命周期的模拟数据**。下一阶段必须让订单成为可处理、可追踪、可闭环的工作流，否则产品无法从"演示系统"走向"可运营系统"。

## 🎯 下一阶段 (Next Phase): 订单生命周期与履约闭环

- **目标**: 让订单从"模拟数据"变为"可处理的工作流"，打通 **下单 → 支付 → 发货 → 完成 / 取消** 全生命周期；B 端可真实管理订单（列表 / 详情 / 发货 / 取消），兑现"订单驱动库存实时变更"的价值承诺。
- **In Scope**:
  - 订单状态机：`PENDING_PAYMENT → PAID → SHIPPED → COMPLETED`，以及 `CANCELLED` 分支（含支付前取消）。
  - 模拟支付：本地模拟支付网关（非真实接入），支付成功推进订单状态并触发库存扣减闭环。
  - B 端订单管理：订单列表（状态过滤 / 搜索）、订单详情（商品快照 / 金额明细 / 优惠券）、发货操作（PAID → SHIPPED）、取消操作。
  - C 端订单状态展示：下单成功后可见订单号与状态（待支付 / 已支付 / 已发货 / 已完成）。
- **Out of Scope**: 真实支付渠道接入（仅模拟）、物流对接与轨迹、售后 / 退款 / 退货、发票、多级分销、复杂推荐算法。
- **Exit Criteria**:
  - ① 订单全生命周期 E2E 通过：下单 → 支付 → 发货 → 完成（`@e2e` 覆盖）。
  - ② B 端订单管理支持发货与取消操作，状态流转正确。
  - ③ 支付前取消场景正确（订单回到终态，库存不受影响）。
- **Explore 护栏**:
  - 必须同时提供 B 端订单管理原型与 C 端订单状态展示原型。
  - 严禁引入任何第三方 UI 组件库（保持零依赖极简）。
  - 状态与金额使用既有契约（`PENDING_PAYMENT/PAID` 等枚举、`priceCents` 财务格式）。
  - 真实业务数据（订单号、商品、金额），拒绝空洞占位符。

## 🗺️ 后续阶段 (Future Phases) 

> 各阶段为高价值方向，进入前需重新评估现状与优先级。

### 阶段 B: 用户资产与忠诚（支撑订单归属与回款）

- **目标**: 沉淀用户资产，让订单、优惠券、回款拥有真实的归属主体。
- **范围**: 用户账户体系（注册 / 登录 / 会话）、多地址管理、基础积分或会员等级。
- **产品理由**: 当前 `user_dev` 占位用户无法支撑"谁的订单、谁的回款"；账户是回款闭环的前置条件。
- **代表性 Epic**: `epic-auth-system`, `epic-crm-basics`

### 阶段 C: 数据洞察与效率工具

- **目标**: 帮助企业通过数据优化经营决策，降低人工统计成本。
- **范围**: 销售报表看板、库存预警、自动补货建议。
- **产品理由**: 订单与库存数据已成型，可沉淀为运营决策输入。
- **代表性 Epic**: `epic-data-dashboard`

### 阶段 D: 回款与应收账款闭环（产品差异化终点）

- **目标**: 兑现"回款节点驱动应收账款看板"的核心承诺。
- **范围**: 应收账款 / 账期管理、回款节点登记、回款状态看板（老板与财务视角）。
- **产品理由**: 这是 `PRODUCT_SENSE` 中与"订单散落、回款在群聊"痛点直接对应的差异化能力，是产品从"电商工具"升级为"运营闭环系统"的标志。
- **代表性 Epic**: `epic-accounts-receivable`
