# 产品路线图 (Product Roadmap)

本文档定义了 OpenSpec-Practice 极简电商系统的高阶业务规划。
AI Agent 在执行 `/opsx:explore`（需求探索）阶段时，**必须首先查阅此文档**，确保新构思的需求符合当前所处的业务阶段，避免过度设计 (Over-engineering) 或做无用功。

---

## 📍 当前所处阶段：Phase 2 - 运营闭环与营销增强

> **当前阶段指导原则**：我们已经有了能跑通的 C 端购买链路，现在的核心是建设 B 端（管理后台）的配置能力，并引入基础的营销工具。任何新增需求都必须同时考虑 B 端的配置管理和 C 端的展示使用。

---

## 🛣️ 路线图规划 (Roadmap Stages)

### ✅ Phase 1: 核心交易链路 (Core Trading MVP) - *已完成*
- **业务场景**: 用户能看到有什么商品，能把商品加入购物车，能点击结算（模拟结账）。
- **包含能力**:
  - 商品列表与详情展示 (Catalog)
  - 购物车管理 (Cart - Add/Remove/Update)
  - 模拟订单生成 (Mock Checkout)
- **技术特征**: 基于内存的仓储 (MemoryRepo)，无用户系统 (游客态)。

### 🔄 Phase 2: 运营闭环与营销增强 (Ops & Marketing) - *进行中 (当前阶段)*
- **业务场景**: 商家能够主动进行营销活动，系统具备实际运营的基础闭环能力。
- **包含能力**:
  - **优惠券系统闭环**: B 端生成/配置优惠券，C 端领取并在结算时核销。
  - **商品管理增强**: 支持商品按分类检索、搜索。
  - **持久化升级**: 从内存存储升级为文件/数据库持久化，确保数据不丢失。
- **Explore 限制**: 不允许在此时引入复杂的推荐算法或多级分销逻辑。

### 📅 Phase 3: 订单生命周期与真实支付 (Order Lifecycle & Payment) - *计划中*
- **业务场景**: 处理真正的资金流，并追踪货物从下单到签收的完整状态。
- **包含能力**:
  - 接入真实支付网关 (如 Stripe 模拟环境)。
  - 完整的订单状态机 (待支付 -> 已支付 -> 待发货 -> 已发货 -> 已完成/已退款)。
  - B 端发货管理界面与物流单号录入。

### 📅 Phase 4: 用户账户与 CRM (Identity & CRM) - *规划中*
- **业务场景**: 沉淀用户资产，提供个性化服务。
- **包含能力**:
  - 用户注册、登录 (JWT Auth)。
  - 多收货地址管理。
  - 基础的会员积分系统 (购买得积分，积分抵扣)。
