# 产品感与业务导向 (Product Sense)

本文档旨在为 AI Agent 提供产品设计和业务决策的上下文，确保 AI 生成的代码不仅仅是“能运行的逻辑片段”，更是“能够支撑中小企业 (SME) 完整商业运营的严肃产品”。

## 1. 核心产品理念

- **可视即价值**: 用户感知到的功能才是有效功能。所有后端的改动，必须有对应的前端原型或 UI 体现。
- **业务闭环优先 (Operational Completeness)**: 我们构建的是一个**可实际运营的中小型电商系统**，绝不是一个只演示前端下单的玩具。任何业务模块都必须考虑完整的生命周期（例如：不仅仅考虑优惠券怎么核销，还要考虑谁来配置？怎么发放？过期怎么处理？）。
- **效率优先**: 界面布局强调逻辑驱动，帮助买家以最短路径完成采购，帮助运营人员高效管理系统，不需要花哨的动画或装饰。

## 2. 目标用户画像 (User Personas)

- **核心买家 (C端)**: 需要快速定位商品并完成采购。他们对界面的响应速度、数据的真实性和操作的明确性（尤其是价格和优惠明细）要求极高。
- **系统管理员/运营人员 (B端)**: 这是维持系统运转的核心角色。他们需要管理后台 (Admin Panel) 来配置营销活动（如发券规则）、管理库存上下架、处理售后订单。他们关注数据的准确性（例如 `priceCents` 的设计）和配置的灵活性。

## 3. AI 决策准则 (特别是 `/opsx:explore` 阶段)

当 AI 在 `/opsx:explore` 阶段权衡方案，或在 `/opsx:apply` 阶段遇到歧义时，必须遵守以下准则：

1. **强制的 B/C 双端视角 (Mandatory B/C Perspective)**: 在探索任何新功能（如“新增优惠券”）时，AI 必须主动向用户提问并澄清 B 端运营逻辑。
   - **禁止行为**：只设计 C 端的展示和使用逻辑。
   - **必须提问**：“这个功能在后台怎么配置？”、“生命周期是怎样的？”、“谁有权限管理？”
2. **如果有两种实现方式，选择对用户最直接的那种。**（例如：直接展示报错信息，而不是用一个模糊的“发生未知错误”）。
3. **拒绝空洞占位符。** 任何时候构建原型，必须代入真实的电商数据（例如：“MacBook Pro 14英寸” 替代 “Test Product A”）。
4. **MVP 原型优先，但拒绝“玩具化”。** 在探索新功能时，优先提供一个可以交互的核心版本，但这个版本必须包含闭环逻辑（例如：B端发券原型 + C端领券/用券原型），等待人类 (HITL) 反馈确认后，再进行复杂的后端开发。
