# Skill 写作规范（writing-for-agents）

用于本仓库所有 `SKILL.md` 的写作。核心目标：让 Agent 每次都按同一流程执行，而不是每次产出不同结果。

## 1. 信息层级

1. **步骤**：Agent 按顺序执行的动作，放 SKILL.md 顶部。
2. **文件内参考**：按需查阅的规则，紧邻相关步骤。
3. **披露参考**：只有部分分支才用到的细节，放 `references/`，用指针引用。

原则：步骤优先；分支性内容下沉到 `references/`；避免把所有内容平铺在 SKILL.md。

## 2. 完成判据

每个步骤都必须有**可检查**的完成判据：
- 模糊判据（如「理解一致」）会导致提前收工。
- 强判据（如「每个承诺项都有 Story 承接」）会驱动实际工作量。
- 判据尽量同时满足「可检查」与「穷尽」。

## 3. 上下文指针

- 指针的措辞决定 Agent 是否会在正确时机打开材料。
- 一个分支只写一个触发词，同义重复的触发词合并。
- 指针前放「引导词」，让 Agent 一眼知道这是什么。

## 4. 引导词

用一个模型已熟悉的词锚定一类行为（如 `frontier`、`tracer bullet`、`design tree`），在文中重复出现，不要每次用一句话重新解释。

## 5. 修剪

- 一个含义只保留一个权威位置。
- 删除「模型默认就会做」的 no-op 指令。
- 删除不再相关的沉积内容。
- 环境已能提供的事实（脚本、配置、目录）不要复述。

## 6. 正面表述

尽量写「要做什么」，少写「不要做什么」。禁止式表述会把被禁行为拉进上下文。只有硬护栏才用禁止式，并同时给出正面目标。

## 7. 本仓库 Skill 结构

```
<skill>/
├── SKILL.md              # 触发 + 步骤 + 完成判据 + 护栏
├── assets/manifest.yaml  # 输出契约：引用中央模板 + 产物路径
├── references/           # 方法、铁律、分支细节
├── scripts/              # 可选：编译/校验
└── examples/             # 可选：脱敏样例
```

- **模板统一放在 `openspec-requirements/templates/`**，由 `assets/manifest.yaml` 引用。
- `assets/` 只放输出契约与技能专属资产；`references/` 放方法与规则。
- 输出模板不得包含过程性说明注释（交付物纯净度）。
