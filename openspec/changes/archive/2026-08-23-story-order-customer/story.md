# Story: C 端订单状态展示 (story-order-customer)

## 用户场景

- **目标用户**: C 端买家。
- **使用动机**: 买家下单/支付后需要持续追踪订单 —— 商家是否发货、是否完成。当前下单后只有一次性成功弹窗，之后订单"消失"，买家无法查看状态。
- **关键目标**: 提供「我的订单」视图，让买家可见全部订单与实时状态（待支付/已支付/已发货/已完成/已取消），补全「下单→支付→(商家发货)→买家可见」闭环（Epic `order-lifecycle` 收官）。

## 范围

### In Scope

- **C 端订单列表**：`GET /api/orders?userId=` —— 返回当前用户全部订单（按创建倒序）。
- **我的订单视图**：header「我的订单」入口；订单列表（订单号/状态/实付/商品摘要）+ 详情展开（金额明细/优惠券/商品明细）+ 状态轨迹。
- **弹窗联动**：结算成功弹窗「查看订单」按钮 → 跳转我的订单视图。

### Out of Scope

- C 端取消订单（由 B 端负责；C 端仅查看）。
- 多用户切换（沿用 `currentUserId`）、订单分页。

## 验收标准 (E2E 用户旅程)

### 旅程 1：买家查看我的订单

- **流程映射**: `L1-06` 履约与完成（C 端订单可见）；`SB-STAGE-06`、`SB-CUSTOMER-06`、`SB-BACKSTAGE-04`

#### 场景：我的订单列表渲染

- **GIVEN** 当前用户存在多个订单（待支付/已支付/已发货/已完成/已取消）
- **WHEN** 买家点击 header「我的订单」
- **THEN** 展示订单列表（订单号/状态中文/实付金额/商品摘要），按创建倒序
- **AND** 仅包含当前用户订单

#### 场景：订单详情与状态轨迹

- **GIVEN** 买家位于我的订单列表
- **WHEN** 买家点击某订单「查看详情」
- **THEN** 展开详情：商品总额/优惠券/折扣/实付 + 商品明细（名称/单价/数量/小计）
- **AND** 展示状态轨迹（待支付→已支付→已发货→已完成 高亮当前状态）

### 旅程 2：支付后跳转查看

- **流程映射**: `L1-05` 支付确认、`L1-06`；`SB-STAGE-05/06`、`SB-CUSTOMER-05/06`

#### 场景：结算成功弹窗查看订单

- **GIVEN** 买家完成下单（PENDING_PAYMENT）并进入结算成功弹窗
- **WHEN** 买家点击「模拟支付」支付成功，再点击「查看订单」
- **THEN** 跳转我的订单视图，该订单显示「已支付」
- **AND** 订单详情中状态轨迹高亮到「已支付」

### 旅程 3：B 端发货后 C 端可见

- **流程映射**: `L1-06`；`SB-STAGE-06`、`SB-CUSTOMER-06`

#### 场景：发货状态同步

- **GIVEN** 买家订单已支付（PAID）
- **WHEN** B 端运营对该订单执行发货（PAID→SHIPPED）
- **THEN** 买家刷新「我的订单」后，该订单显示「已发货」，状态轨迹高亮到「已发货」
