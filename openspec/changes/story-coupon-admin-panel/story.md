# Story: B 端极简运营后台 (story-coupon-admin-panel)

## 用户场景

- **目标用户**: 电商运营人员（B 端）。
- **使用动机**: 运营需要自主创建营销活动所需的优惠券（满减券 / 折扣券）并发放给指定用户，而不依赖开发同学手工写入种子数据。
- **关键目标**: 打通“运营配置 → 单人发放 → C 端结算核销”闭环，让 Story 1 交付的智能结算引擎有真实的券数据可消费。

## 范围

### In Scope

- 优惠券规则配置：名称、类型（FLAT / PERCENTAGE）、优惠值、使用门槛（minSpendCents）、有效期。
- 创建即生效：券创建后直接进入 `ACTIVE` 状态（简化 DRAFT 中间态），可被发放并参与最优推荐。
- 手动单人发券：将已配置的券发放给指定 userId，建立券与用户的持有关系（`UNUSED`）。
- 券列表视图：展示类型、优惠内容、门槛、有效期、状态与已发放数量。
- 发放记录回流：发放动作实时沉淀为操作记录（时间 / 券 / 用户 / 操作人）。

### Out of Scope

- 批量发放、自动领取、用户主动领券。
- 券的停用、删除与编辑。
- 商品级 / 品类级适用范围（保持全场通用）。
- 运营数据报表与营销效果分析。
- 退款时的券回滚（已移至 Roadmap Phase 3）。

## 业务规则

| 规则ID | 规则描述 | 触发条件 | 期望结果 | 备注 |
| --- | --- | --- | --- | --- |
| R-ADMIN-001 | 创建即生效 | 运营提交合法的券规则表单 | 券状态为 ACTIVE，立即可发放、可被结算引擎推荐 | 简化 DRAFT 态，对应状态机 `DRAFT → ACTIVE (CouponPublished)` |
| R-ADMIN-002 | 折扣券比例约束 | 创建 PERCENTAGE 券 | 折扣值必须大于 0 且小于 10（如 9 表示 9 折），否则拒绝创建 | 折扣计算沿用 R-COUPON-002 的向下取整规则 |
| R-ADMIN-003 | 满减券金额约束 | 创建 FLAT 券且设置了门槛 | 减免金额必须小于门槛金额，否则拒绝创建 | 防止“满 100 减 100”类异常规则 |
| R-ADMIN-004 | 单人发放 | 运营执行发券动作 | 每次仅能填写一个 userId，格式须为 `user_<数字>` | Epic 探索已确认不做批量 |
| R-ADMIN-005 | 重复发放拒绝 | 目标用户已持有同一张券（UNUSED） | 拒绝发放并提示“该用户已持有此券” | 防止同一用户叠加持有 |
| R-ADMIN-006 | 发放即生效 | 发放动作成功 | 券以 UNUSED 状态绑定 userId，即刻进入该用户结算时的候选券集合 | 对应 L3-01「识别候选券」输入 |
| R-ADMIN-007 | 全场通用 | 任意券被创建 | 不设置商品 / 品类适用范围，全部按全场通用处理 | 与 Epic 探索结论一致 |

## 验收标准 (E2E 用户旅程)

### 旅程 1：运营创建优惠券规则

- **流程映射**: `SB-OPS-03`（运营配置活动）、`SB-BACKSTAGE-03`（券规则持久化）

#### 场景：创建一张折扣券并成功生效

- @e2e
- **GIVEN** 运营人员王琳登录运营后台并进入「营销中心 / 优惠券管理」
- **WHEN** 王琳填写：名称“中秋特惠 8.5 折券”、类型 PERCENTAGE、折扣 8.5、门槛 ¥300、有效期 2026-10-15，并点击「创建并生效」
- **THEN** 券列表新增一条记录，状态为 ACTIVE，已发放数量为 0
- **AND** 该券出现在「手动发券」的可选券集合中

#### 场景：非法规则被拒绝

- @e2e
- **GIVEN** 运营人员王琳进入新建优惠券表单
- **WHEN** 王琳填写：类型 FLAT、减免金额 ¥120、使用门槛 ¥100，并点击「创建并生效」
- **THEN** 系统拒绝创建并提示“减免金额不能大于或等于使用门槛”
- **AND** 券列表不新增任何记录

### 旅程 2：手动单人发券

- **流程映射**: `SB-OPS-03`（发券活动）

#### 场景：发放成功并回流记录

- @e2e
- **GIVEN** 券列表中存在 ACTIVE 状态的「新客专享满减券」（满 ¥100 减 ¥20）
- **WHEN** 王琳在该券上点击「发券」，输入用户 ID `user_1003` 并确认发放
- **THEN** 系统提示发放成功，该券的已发放数量加 1
- **AND** 最近发放记录顶部新增一条：「新客专享满减券 → user_1003」，券状态为 UNUSED

#### 场景：重复发放被拒绝

- @e2e
- **GIVEN** 用户 `user_1003` 已持有「新客专享满减券」（UNUSED）
- **WHEN** 王琳再次对 `user_1003` 发放同一张券
- **THEN** 系统拒绝发放并提示“用户 user_1003 已持有该券，请勿重复发放”
- **AND** 已发放数量与发放记录均不发生变化

### 旅程 3：发放的券在 C 端结算被消费（闭环验证）

- **流程映射**: `L1-04` 下单结算 → `L2-02` 加载结算上下文 → `L3-01` 识别候选券；`SB-STAGE-03` / `SB-CUSTOMER-03`

#### 场景：新发放的券进入最优推荐候选集

- @e2e
- **GIVEN** 用户 `user_1003` 刚被发放「新客专享满减券」（满 ¥100 减 ¥20，UNUSED）
- **AND** 该用户购物车商品总额为 ¥156.00
- **WHEN** 用户进入结算确认页面
- **THEN** 「新客专享满减券」出现在该用户的可用券集合中
- **AND** 系统按既有最优券规则计算并展示减免金额 ¥20.00 与实付金额 ¥136.00
