💡 核心理念

“以规格为源”，确保代码与测试始终与设计保持一致，解决传统开发中“文档落后于代码”的顽疾。AI 时代，Spec 是人与机器沟通的“共同语言”。

📦 本期实战案例：微型电商系统演进

本项目 ecommerce-mini 已具备基础商品目录功能。本次任务是通过 SDD 流程为其添加“购物车”与“下单支付”的核心能力。

技术栈限制：
  • • 后端: Node.js v20+, 零依赖, 原生 HTTP
  • • 前端: Vue 3 + Tailwind (单文件组件)
  • • 存储: 内存 Map / JSON 文件

新需求挑战：

  • 需求 1 购物车功能：添加商品、修改数量、最大数限制(99)。
  • 需求 2 订单核心：购物车结算生成订单，原子扣减库存。
  • 需求 3 质量要求：核心接口 p99 < 100ms，需自动化测试证据。

议程与引导 (Timeline)

总计 180 分钟
01 30 min

理论导入：AI 研发新范式

深入理解 AI 研发新范式、SDD (Spec-Driven Development)、原型驱动开发以及 Harness 质量门禁的核心理念与流程全景图。

📊 SDD 入门讲解 (PPT) 📘 OpenSpec 用户手册 🧠 AI 工作流深度复盘
02 15 min

环境准备：熟悉“武器库”

熟悉项目代码仓与 SDD 脚手架，了解预置的 Skills 和常用命令，完成分组与角色分工。

角色分工：

  • • PM 实习生：负责维护 Proposal & Spec，进行原型验收
  • • Dev 实习生：负责 Plan & Apply，确保代码通过质量门禁
# 验证本地环境
node -v # v20+
python --version # 3.10+
openspec --version
03 25 min

需求理解 & 原型设计

收到需求 → Brainstorm 发散 → 用 HTML 快速画出可交互原型 → 输出 proposal.md

/opsx:propose
"构建一个小型电商网站 MVP，包含购物车功能，支持添加商品、修改数量，限制最大加购数(99)。"
⚠️ 关键断点 (Checkpoint)： AI 生成原型后，PM 必须进行视觉确认：“交互流向和界面效果是否符合预期？”
04 30 min

需求规格化 (Spec Definition)

基于原型将需求结构化，输出 spec.md，明确功能需求、验收标准与交互细节，通过组内 Spec Review。

Spec 核心要素：

  • • 必须包含 Delta Header (ADDED/MODIFIED)
  • • 必须定义 Requirement，并标注 Priority 和 Rationale
  • • 必须使用 Given/When/Then (Gherkin) 格式编写 Scenario
openspec validate <change-name> 执行格式强制校验
05 25 min

技术规划 (Tech Planning)

基于 Spec 拆解技术实现计划，输出 plan.md，细化 Task 列表与依赖关系，确认技术可行性。

Dev Checklist：

  • [ ] 每个 Requirement 是否都有对应的技术 Task？
  • [ ] 是否考虑了数据存储（内存 Map / JSON 文件）的更新？
  • [ ] 是否明确了自动化测试的实现方式？
06 20 min

代码实现 & 测试 (Apply & Harness)

按 Plan 逐步编码实现，产品实习生实时验收，完成核心功能开发并通过 Harness 自测。

/opsx:apply
"请根据规范和计划执行代码实现，确保核心逻辑覆盖单元测试。"
Harness 质量门禁验证：
npm test (逻辑校验) p99 < 100ms (性能指标) 原型 1:1 比对 (UI 验收)
07 25 min

Demo & 复盘

各组演示成果，讲师引导复盘 SDD 全流程中的关键体会与落地建议。演示如何通过 /opsx:sync 和 /opsx:archive 完成资产沉淀。
