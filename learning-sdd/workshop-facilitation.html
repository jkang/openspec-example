💡 核心理念

“以规格为源”，确保代码与测试始终与设计保持一致。OpenSpec 倡导的新范式：意图 -> 探索 -> 提案 -> 原型 -> 规范 -> 实现 -> 同步 -> 归档。

📦 本期实战案例：优惠券系统集成

本项目 ecommerce-mini 已具备商品目录、购物车与订单结算等基础功能。本次任务是通过 SDD 流程为其添加“优惠券核销与价格抵扣”的核心能力。

技术栈限制：
  • • 后端: Node.js v20+, 零依赖
  • • 前端: Vue 3 + Tailwind
  • • 存储: 内存 Map / JSON 文件

新需求挑战：

  • 需求 1 折扣券：输入 SUMMER20 全场 8 折，需实时计算抵扣金额。
  • 需求 2 满减券：输入 FLAT10 满 100 元减 10 元，需校验门槛。
  • 需求 3 质量门禁：核心计价逻辑 100% 单元测试覆盖，防止“负数订单”。

实战演练 (Execution Workflow)

遵循 OpenSpec v1.8.0 范式
01 15 min

理论导入：AI 协作新范式

从“人写代码”转向“人把关规范”。理解 SDD 如何通过确定性的流程消除需求偏差。

🧠 AI 工作流深度复盘 📘 OpenSpec 用户手册
02 10 min

环境准备：Setup & Check

依据 README.md 完成工具链初始化与环境检查。

# 1. 安装 OpenSpec 命令行工具
npm install -g @fission-ai/openspec@latest
# 2. 为 Trae/Cursor 生成 AI 协作技能
openspec init --tools trae
# 3. 验证基础依赖
node -v # 应 >= v20.19.0
python --version # 应 >= v3.10

Review 要点：

  • 确认 `openspec --version` 能正确返回版本号
  • 确认 `.trae/skills/` 目录下已生成对应的技能定义文件
03 10 min

Explore：意图对齐与方案探索

关键目标：意图与架构对齐

在动工前，执行结构化 5 步法探索。让 AI 调查现有架构、明确业务意图与设计思路，并给出需求拆分建议，生成 idea.md。这是所有变更的源头。

/opsx:explore
"我想在结算流程中加入优惠券功能。请分析现有价格计算逻辑及集成点，并按 5 步法给出方案建议。"

Review 要点：

  • 确认 idea.md 是否包含：1.业务意图、2.设计思路、3.拆分建议、4.架构影响、5.确认结论
  • 检查 AI 对现有逻辑（如 order.js 的计价逻辑）的理解是否准确
04 20 min

Propose & Prototype：提案与原型

关键目标：视觉对齐

正式发起变更，并要求 AI 生成可交互的 HTML 原型以确认 UI 效果。

/opsx:propose coupon-integration
"实施折扣券核心功能：增加优惠券输入框，并支持 SUMMER20 (8折) 的实时预校验与抵扣。"
05 10 min

Plan：规划审查

关键目标：路径对齐审查

审查 AI 自动生成的 `tasks.md`。确保技术路径与 `spec.md` 中的需求 100% 匹配，特别是数据结构的修改建议。

- [ ] 在 src/domain/types.js 中增加 Coupon 类型定义
- [ ] 修改 src/services/order.js，在 createOrder 中注入优惠计算拦截器
- [ ] 在 __tests__/unit.spec.js 中增加优惠计价的数学准确性测试

Review 要点：

  • 每个 Requirement 是否都有对应的技术 Task？
  • 是否考虑了数据存储（内存 Map / JSON 文件）的更新？
06 25 min

Apply & Harness：实现与质量门禁

关键目标：确定性交付

执行代码生成，并通过自动化测试验证交付质量。

/opsx:apply
"请根据规范和计划执行代码实现，确保核心逻辑覆盖单元测试。"
PASS src/services/order.spec.js
✓ should apply 20% discount for SAVE20 (12ms)
✓ should reject expired coupons (5ms)
07 25 min

Update：需求迭代与增量规划

关键目标：增量增强

实现第一版后，发现之前的 Spec 不够全面（例如漏掉了过期逻辑），使用 Update 指令进行增量更新。

/opsx:update
"增加『满 200 减 30』的阶梯优惠规则，并确保优惠券过期后不可使用。请更新 Spec 和相关 Task。"
Review 要点： 观察 AI 如何在不破坏现有结构的情况下，增量更新 `design.md` 和 `tasks.md`。
08 15 min

Sync & Archive：资产沉淀

将变更同步至主规范，并归档开发记录，确保团队知识库持续演进。

/opsx:sync # 将增量同步到 root specs/
/opsx:archive # 移动到 archive 目录

Review 要点：

  • 确认 `openspec/specs/` 下出现了新的 `coupon-management` 目录
  • 确认 `openspec/changes/` 下的活跃变更已清空
09 25 min

Demo & 复盘总结

展示最终交付的功能，分享在 SDD 流程中“人机协作”的体会，总结 OpenSpec v1.8.0 的核心价值。

成果演示

  • • 优惠券输入后的实时金额抵扣展示
  • • 后端折扣逻辑的数学准确性验证
  • • 自动化测试报告与 100% 覆盖率证据

复盘总结

真实项目迁移建议

  • • 业务上下文增强：需提供更完备的 Business Context 文档
  • • 领域划分与 Baseline：需明确业务领域边界及基线 Specs
  • • Skill 深度定制：针对原型设计等环节，集成内部设计规范与组件库

下一步学习建议

  • 1. 学习应用 Harness 实践
    - 完善 AGENTS.md, feature-list.json, progress.md
    - 引入自动化测试（如基于 Cucumber 的 BDD 测试）
    - 增加 Validate 节点：验证 Apply 后自动化测试是否真正运行并通过
  • 2. 强化产品规划节点
    - 在 Explore 后增加整体方案设计与需求拆分
    - 针对每条 Story 独立进入 Propose 流程实现精准交付
